4. Business Rules That DA2 Must Implement
Every product belongs to exactly one ProductCategory; categories may be hierarchical.
A PurchaseOrder belongs to exactly one Supplier and contains one or more PurchaseOrderLine rows.
A Shipment belongs to one PurchaseOrder and supports partial/multiple deliveries.
Received goods enter WAREHOUSE-type InventoryLocation, not SHELF directly.
InventoryLocation is one unified table; WAREHOUSE and SHELF are distinguished by location_type. A shelf may have a parent warehouse.
InventoryStock resolves Product × InventoryLocation and stores the live stock snapshot.
Sales consume stock only from SHELF-type locations.
A SalesTransaction may have one customer or NULL for guest checkout and must have one cashier.
A SalesTransaction may have multiple Payment rows for split payments.
When shelf stock falls below reorder_threshold, create a RestockEvent representing warehouse→shelf movement.
When warehouse stock falls below reorder_threshold, create a ReorderTrigger and support generation of a PurchaseOrder.
Every stock-affecting event must create an InventoryTransaction ledger row.
Do not physically delete transactional/audit history; preserve history through status/controlled operations.

7. Important Oracle Conversion Rules
Use VARCHAR2 instead of MySQL VARCHAR where appropriate; use NUMBER(p,s) for numeric values.
Do NOT use MySQL AUTO_INCREMENT. Use Oracle GENERATED BY DEFAULT AS IDENTITY or sequences consistently.
Do NOT use MySQL ENUM. Use VARCHAR2 plus CHECK constraints.
Oracle DATE/TIMESTAMP should be used for dates/times.
Oracle SQL does not support MySQL-style ON UPDATE CASCADE. Do not invent it.
Use CREATE OR REPLACE PROCEDURE/FUNCTION/TRIGGER.
Use / after standalone PL/SQL program units when running in SQL*Plus/SQL Developer script mode.
Use SET SERVEROUTPUT ON before DBMS_OUTPUT demonstrations.
Handle the InventoryLocation self-FK carefully: create the table first, then add the self-referencing FK if needed.
Create parent tables before child tables. If circular dependency appears, use ALTER TABLE to add the FK after both tables exist.
Do not use BOOLEAN as a table column type unless the target Oracle version/environment explicitly supports it; VARCHAR2/NUMBER + CHECK is safer for a university Oracle lab.
Do not implement unsupported/undefined features merely because the conceptual report mentions them.
